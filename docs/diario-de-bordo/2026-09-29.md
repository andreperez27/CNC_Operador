## Convite resgatado não marca no painel — causa raiz e correção

- **Relato:** após o resgate, o painel não mostrava "Usado" e o botão
  ATUALIZAR não parecia recarregar. SQL no Dashboard: `status = 'ativo'`,
  `usado_em`/`usado_por` nulos — ou seja, o resgate **nunca chegou ao
  banco** (não era problema de listagem).
- **Rastreio (evidências, não suposição):** `supabase functions list`
  mostrou `resgatar` em **v3** (ACTIVE), deployada em 2026-09-27 =
  commit `295d466`; o fix `cd0bca8` (admin não consome / beta existente
  estende validade) está no git mas **nunca foi publicado**. A v3 também
  marca `usado`, então versão não era a causa. Chamada real à função
  publicada: token falso → **410** (anti-enumeração OK) e
  `listar-convites` com anônimo → **403** (admin-check OK): backend
  saudável, defeito no cliente.
- **Causa raiz:** o aceite vivia só no `LoginPage`, que não monta com
  sessão válida. Admin testando o próprio fluxo e beta em dia abriam o app
  normalmente, com o token preso na URL e `resgatar` **nunca chamado** —
  sem erro em tela (falha silenciosa).
- **Correção:** `AuthGate` passa a rodar o aceite também em `granted` e
  `denied` (inativo/expirado), com decisão pura em
  `src/features/auth/conviteFlow.js`; `loading`/`signed-out`/
  `denied`+`no-profile` seguem no LoginPage (sem POST duplicado) e estado
  desconhecido não dispara resgate. Falha mostra mensagem; `note:
  'already-admin'` avisa que o convite **não** foi consumido.
  Coberto por `tests/conviteAuthFlow.test.js` (9).
- **Validação:** `npm test` **295/295 (18 arquivos)**, `npm run lint`
  **0 erros, 13 warnings**, `npm run build` OK precache 39 entradas
  (1365.90 KiB).
- **Pendente manual:** `supabase functions deploy resgatar` — sem isso a
  v3 consome o convite do admin e não estende a validade de beta
  existente (comportamento antigo, agora visível na tela).

- **RECARREGAR morto — dois bugs reais no `UpdateBanner.jsx`:**
  1. `useRegisterSW()` retorna `needRefresh` como **tupla**
     `[boolean, setter]` (sempre truthy) — o aviso nunca sumia;
  2. com `registerType: 'autoUpdate'`, o `updateServiceWorker()` do
     `vite-plugin-pwa@1.3.0` é **no-op de propósito** (`if (!auto)` no

  esperando; botão ativa via skip-waiting + recarrega; sem reload
  automático no meio da operação) + desestruturação da tupla.
